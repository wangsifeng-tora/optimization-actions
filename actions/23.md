## 2. Motivation

Registering the Triton W4A16 GEMM and its fake implementation keeps the intended quantized kernel visible to eager dispatch and compilation.

## 3. Before vs. after

| Behavior | Before | After |
|---|---|---|
| Operation exposure | The Triton W4A16 implementation may be callable only through an eager code path. | The implementation is exposed through a registered custom operation. |
| Compilation metadata | Graph tracing has no registered fake implementation for the operation’s shapes and metadata. | The fake implementation supplies compile-time output metadata without launching the Triton kernel. |
| Kernel selection | Compile mode may replace or lose the intended W4A16 operation. | The compiled graph retains an explicit W4A16 custom-operation boundary. |
| Runtime dispatch | Eager and compiled paths can resolve different implementations. | Both paths resolve the registered operation and its Triton implementation when supported. |
