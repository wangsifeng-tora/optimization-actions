## 2. Motivation

Vectorizing the FP32 `moe_sum` reduction and removing fixed top-k assumptions makes routed-expert combination follow the actual routing width.

## 3. Before vs. after

| Behavior | Before | After |
|---|---|---|
| Reduction implementation | `moe_sum` reduces expert contributions through the existing scalar or non-vectorized path. | `moe_sum` reduces contributions through vectorized FP32 operations. |
| Top-k contract | Reduction indexing is tied to a fixed top-k route width. | Reduction indexing follows the runtime top-k dimension. |
| Expert contribution layout | The combine stage supplies contributions to fixed-width reduction logic. | The combine stage supplies contributions using the actual arbitrary-top-k shape and strides. |
| Unsupported route widths | A route width outside the fixed assumption is not represented by the optimized reduction. | Supported route widths use the generalized reduction while the existing compatible fallback remains available. |
